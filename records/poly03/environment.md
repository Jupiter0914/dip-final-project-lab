# 执行环境、资源与工具辅助

Windows 11，既有 E:/Miniconda/envs/pytorch_cv/python.exe（Python 3.12.13），主机总内存 16,489,648,128 字节，开始探测时可用约 3.09 GB。主要工作是单线程 OpenCV、NumPy、SciPy、ContourPy 和 GEOS，版本锁见 configs/poly03/requirements.txt 与前置的 POLY02 环境说明。CGAL 5.4 使用本机既有 Ubuntu 22.04 WSL、g++ 11.4、Boost 1.74、GMP 和 MPFR，独立解包并构建。官方库与确定性平局诊断包分开，后者不作为速度对照。没有模型训练或新增付费算力。

本轮由 Codex 及三个获授权子任务分别处理完整蒙版、单圈实验、官方基线及细部诊断。论文方法与公式通过出版社、作者正文或官方文档核对；Kolesnikov–Fränti 作者站文件直连发生 TLS 失败，改从可读的作者 PDF 检索正文核对 §3.1–3.3 及实验。Li 等 CVPR PDF 已从 CVF 下载并渲染方法页。数据全部来自 POLY02 旧缓存；未抓取新的 LEMS/Oxford/MPEG 实例用于选题。

研发顺序：先核对干净 POLY02 提交并在独立分支建问题记录，按输入特征选择 32 张，完整精度回放通过，建立基础分配及删插对照。观察到排序基本可加后，先留后续开发规则，再测可行性探针、固定相位简单替代和同时间下的文件检查点。公平计时移除了仅用于排序诊断的额外双重打分。原始诊断时钟与正常时钟分别保存；冷启动、搜索未达预算与没有移动均没有删行。对官方 CGAL 跨进程差异，保留两轮完整文件及额外敏感性对照，没有事后择优。

报告的源级区间为开发集原图配对百分位自助法，主完整蒙版比较 5,000 次、种子 30621。所有预算、部件、重复进程和随机种子均不作为新增独立源。实际截止时间试验在每个观察点选最后一个已经生成字节的检查点，在源内平均三个重复。源输入读取、磁盘落盘、评估指标统计与算法的内存编码/解码时间分开。全组主表的共享准备路径按各方法所需的真实执行段累加，未将起点免费赠给后处理。第二次完整复跑将可复用画布的创建也纳入计时，全量行见 results/poly03/repetition/per_image.csv。置信区间反映这批分层源的变异，不能当作自然总体推断。
