# POLY04 编码器、基线和同步交付

输入为已在内存的单通道 0/1 二值数组。各方法共同使用 POLY03 的 PM31、四分之一像素等值线、OpenCV LINE_8 完整画布解码和原始数字结构对应。前景为 8 连通，背景为 4 连通。每份合格文件还须满足原环父子关系、有限孔与前景部件的双向位置对应、邻接关系和实际目标点数。[PM31 定义](../../report/poly03/format.md)

## 输入与四种状态

prepare_input 先检查数组维度、字段范围、实现画布上限、二值取值和可支持的高精度等值线，再把高精度每一圈实际画回原尺寸并作奇偶合成，逐像素核对输入。通过后才检验 B ≥ 10+16R，目标点数取 min(全部高精度顶点数, floor((B−10−4R)/4))。空图可以用 10 字节表示，单像素和单像素孔也经过测试。状态为 success、below_proved_lower_bound、search_no_valid_output 或 unsupported_representation。只有已定义的 Unsupported 会转成不支持状态。几何检查中，已知的非简单环/退化、边界相触、相交以专用的 GeometryRejected 表达；程序错误、运行环境错误和任意未预期的 ValueError/RuntimeError 继续上抛。

生产入口、旧 anytime 初始化与回调、repair 与相位对照、旧导出和完整批处理、旧离线审核均共用该准备判断。既有审核继续用另一套数字标记与像素路径复算。POLY03 的旧标签、旧表、文件和代码快照可独立检出。

## 生产种子

所有 DP 方法在同一个确定的 RDP 逐圈层级上计算可加 XOR 曲线。先求满足总点数的独立误差 DP 分配和周长分配。生产使用 `poly03.allocation.candidates` 的有限池：二圈时列出满足总点数的可用层级组合；其他环数从可用的 DP/周长分配出发，将 1、2、4 个点从一圈转到另一圈。按逐圈 XOR 和、再按分配的字典序排序。若超过 40，保留基础分配与排名前 20，按等距下标采样后按原顺序补到 40。首个通过共同结构检查的解成为起点。穷尽只能表明本次有限池未找到合格输出。`repair.ordered_allocations` 用后缀 DP 和子问题分割做真正的次优枚举，作为旧开发诊断单列。

原版 CGAL squared 独立从高精度原环建网并简化。每次调用都实际求解，不借用另一行的起点。记录原生返回状态、环整数坐标、可打包时的原生 PM31 和 SHA。CGAL 独立行输出原生顺序。CGAL 后处理行逐圈找到原始高精度点下标，检查成员唯一且沿原环正向或反向循环有序；若为反向，保留首顶点并反转其余顺序。再验证映射前后整幅重建逐像素相等。任何环数/点数、原环身份、矢量或数字结构不符均以该方法自身失败登记。程序/worker 错误中止并暴露。原版的等代价选择会随进程历史变化。[POLY03 的真实复跑](../../report/poly03/cgal-variation.md)

## 每轮候选

每圈所有允许删除的位置都用完整画布计算删后孤立环 XOR 改变量。每条边在其两个端点所夹的原高精度弧段中，取距弦最远的源顶点、弧索引中点，去重后分别计算插后孤立环 XOR 改变量。可加预评分为单删和单插代理代价之和。删除点和接收边用操作前下标，同圈不能选与删点相邻的边。三角环在修正规则中可以给本圈对边补一个点，最终仍为三点；其 K−1 删点代理使用同一个完整画布上的双点 LINE_8 线迹，不会编码该中间状态。跨圈供体始终要求至少四点。

| 方法 | 预筛与目标 |
|---|---|
| seed | 可行 DP 起点，立即交付 |
| within_old | 旧规则，全局删除前 5、插入前 10，分别并入每圈最佳，再筛同圈非相邻组合；禁用三角供点 |
| within_full_oldtri | 全体同圈非相邻组合按相同代理排序，禁用三角供点 |
| within_full | 全体同圈非相邻组合，允许本圈三角替点 |
| cross_oldtri | 旧全局短表、可跨圈，禁用三角供点 |
| cross_full_oldtri | 全体可选同圈与跨圈组合，禁用三角供点。与 cross 只差三角规则 |
| cross | 使用与 within_full 相同的同圈合法集合，并允许跨圈供点 |
| cgal | 原版 CGAL squared 合格起点 |
| cgal_within | 原版 CGAL squared 合格起点加同一个 within_full |
| exact | 与 cross 相同提案，按真实整图 XOR 排序 |

组合按 (代理代价和, 供体圈, 供点下标, 接收圈, 边下标, 新坐标) 升序取前 24 个，组合不足则全部使用。具体实现将每个供点的接收序列按此键有序生成，用精确有序归并取前 24，与穷举所有组合再排序结果一致。候选的组合合法性初筛在此步，实际矢量/数字验收仍在最终环上完成。R=1 时修正版跨圈可选和强圈内有相同的组合和搜索规则。各组记录 eligible_pairs、proposed_pairs、接受数、跨圈与三角动作、接受/拒绝的完整回填检查数。

可加路径在实现联合操作后，对所有改动圈完整画布回填，计算最终逐圈 XOR 之和；只保留该和严格低于当前值的候选。按这个最终代价及原预排次序依次试探，须真实整图 XOR 严格下降并完整通过几何与数字对应才接受。精确路径改用整图的严格下降和排名，用全画布奇偶公式复用未变圈，最终验收独立重画全部圈。两者在一般输入上可能有不同筛选或排名。针对筛选遗漏的 `poly04.engine_audit.audit_screen` 单列、在计时之外实际计算两种目标，并区分严格下降但不合法、以及可行且被筛掉的提案。

## 时间与文件

每次 encode 从 in-memory 原数组开始使用 perf_counter_ns。初始化、所有候选生成和排序、完整光栅化、合法性、循环下标映射、PM31 序列化与同步回调都在计时内。第 0 个检查点是合法种子，后续只在接受一项严格改善后交付。serialized_ms 紧接 pack，delivered_ms 为调用接收器前的时间戳；调用方在回调入口用相同 start_ns 记录 received_ms，主截止使用这个可观察的实际接收时间，一轮超过截止的结果不会追溯计入。end_ms 在搜索停止后记录，return_ms 另含仅为归档组装的原生坐标列表/哈希。成功 CGAL 原生 PM31 尽量直接复用已交付同一 bytes。图像读盘和解码、输入清单及结果落盘、离线质量评价、冷启动的政策和实耗另列。

旧 POLY03 静态主表为两轮，检查点生产实验最多八轮。每轮边界检查 max_ms；无候选改善、轮数达到上限或到时均停止，单轮和初始求解允许超过时点。成功状态与截止前已有输出分别登记。已有正常种子、三角/下界/不支持/程序错误、穷举前 24 与真实早交付的检查见 [引擎证据](engine-check.json)。
